# AI Avatar Agent — дизайн

**Дата:** 2026-08-16
**Задание:** `projects/5-ai-avatar-agent/TASK.md`
**Каталог реализации:** `projects/5-ai-avatar-agent/`

Мультимодальный агент-проводник по ресторанам Алматы: принимает текст, фото и голос,
ищет данные через два собственных MCP-сервера, отвечает текстом, а по запросу —
аудио клонированным голосом и видео с говорящим аватаром.

## Цели и ограничения

- **Цель:** максимум баллов по рубрике при минимальных расходах. Все 100 обязательных
  баллов плюс бонусные +10 за оптимизацию стоимости.
- **Бюджет:** разрешено ~$15–20, планируем уложиться в $5–8.
- **Ответы и интерфейс** на русском языке.
- **Платные вызовы:** реальные вызовы fal.ai разрешены, но перед первым вызовом
  каждого типа (клон голоса, TTS, видео) требуется явное подтверждение владельца.
- Всё, что можно отладить без денег, отлаживается на моках и фикстурах.

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Мозг агента | `openai` SDK напрямую + свой мост к MCP | Полный контроль над историей, токенами и логом вызовов; минимум зависимостей; нет риска сломаться об версии LangChain |
| MCP-серверы | Свои, на `fastmcp` 3, транспорт stdio | Требование спеки: отдельный процесс, доступ через MCP-протокол |
| Источник данных | `playwright` (Python) внутри наших MCP-серверов | Детерминированный парсинг, не тратит токены, тестируется без LLM |
| Аватар | `fal-ai/creatify/aurora` | Рекомендация спеки; Kling v2 standard остаётся запасным вариантом в конфиге |
| ASR | `fal-ai/whisper` | Уже проверен в `seminar/19-multimodal-generation`, ключ тот же, что для остального fal |
| TTS | `fal-ai/minimax/speech-02-hd` | Проверен, поддерживает клонированный голос |
| Клон голоса | `fal-ai/minimax/voice-clone` | Разовая операция ~$0.50, результат кэшируется |
| Третий MCP-сервер (ABR Group) | Не делаем | Баллов не даёт (25 из 25 закрываются двумя), добавляет хрупкости |
| Тесты | `pytest` на фикстурах | Ни один тест не ходит в сеть и не тратит деньги |

### Отклонения от буквы задания

1. **Playwright как библиотека, а не `@playwright/mcp`.** Спека формулирует
   «использовать Playwright MCP или Stagehand MCP для browser automation».
   Мы поднимаем браузер внутри собственного MCP-сервера. Требование «MCP-сервер —
   отдельный процесс, LLM вызывает инструменты через function calling» выполняется
   полностью; отличается только то, чем именно управляется браузер.
   **Митигация:** отдельный абзац в README с объяснением решения.
2. **ABR Group не реализуем** — помечен в задании как бонус, баллов в таблице нет.

### Ошибки в сниппетах задания (проверено по рабочему коду семинара 19)

- `fal-ai/minimax/voice-clone` возвращает **`custom_voice_id`**, а не `voice_id`.
- `fal-ai/minimax/speech-02-hd` принимает голос как вложенный объект
  **`voice_setting: {voice_id, speed, vol, pitch}`**, а не плоским полем `voice_id`.
- Сниппет Creatify Aurora из задания в репозитории никем не запускался; при первом
  реальном прогоне возможны расхождения в именах полей ответа.

## Архитектура

Три процесса. Gradio-приложение выступает MCP-клиентом и поднимает два MCP-сервера
как дочерние stdio-процессы. Серверы не знают про LLM, агент не знает про Playwright.

```
вход: текст | аудио | фото
   │
   ├─ аудио → fal-ai/whisper ─────────► текст вопроса
   ├─ фото  → сохраняем локально, кладём в сообщение как image-контент
   │
   ▼
agent loop (openai SDK, tools = MCP + локальный skill)
   │  ├─ twogis__search_restaurants(query, location)
   │  ├─ chocolife__search_deals(category, city)
   │  └─ analyze_restaurant_photo(image_path)
   │  цикл: максимум 6 tool-вызовов на ход, история в gr.State
   ▼
текстовый ответ (15–30 секунд речи) — показывается всегда и сразу
   │
   └─ по кнопке «Озвучить»:
         voice_id из кэша (клон делается один раз за проект)
         → fal-ai/minimax/speech-02-hd  → mp3
         → fal-ai/creatify/aurora       → mp4
```

## Компоненты

### MCP-серверы

Общая форма: `fastmcp` 3, stdio, один процесс на источник. Инструменты возвращают
Pydantic-модели — FastMCP выводит из них JSON-схему для LLM.

**`twogis`** — `search_restaurants(query: str, location: str = "Алматы", limit: int = 8) -> SearchResult`
Поля `Restaurant`: `name`, `address`, `rating`, `price_range`, `cuisine`,
`working_hours`, `phone`.

**`chocolife`** — `search_deals(category: str = "рестораны", city: str = "Алматы", limit: int = 8) -> DealsResult`
Поля `Deal`: `title`, `restaurant_name`, `original_price`, `discount_price`,
`discount_percent`, `description`, `url`.

Общий каркас в `mcp_servers/common/`:

- один headless Chromium на процесс, а не на запрос;
- disk-кэш с TTL 24 часа, ключ — нормализованный запрос;
- троттлинг не менее 2 секунд между навигациями;
- ретрай ×2 с экспоненциальным бэкоффом;
- флаг `--offline`: отдаёт фикстуры вместо браузера.

**Честность данных.** Если парсер не нашёл ни одной карточки, инструмент возвращает
пустой список и заполненное поле `error`. Системный промпт обязывает агента сказать,
что данные получить не удалось. Захардкоженных ответов нет нигде.

### Агент

`agent/llm.py` — асинхронный цикл: история + tools → если пришли `tool_calls`,
исполняем **все** из пачки и дописываем результат на каждый (иначе следующий запрос
к API падает) → повторяем. Потолок 6 вызовов за ход; при исчерпании агент отвечает
тем, что успел собрать.

`agent/tools.py` собирает единый реестр из `fastmcp.Client.list_tools()` по каждому
серверу плюс локальные функции. Имена MCP-инструментов префиксуются именем сервера
(`twogis__search_restaurants`). Диспетчер по имени решает, звать MCP или локальную
функцию; для LLM разницы нет.

**Память.** История сообщений живёт в `gr.State` (изолирована по сессии), целиком
уходит в каждый запрос. Держим последние 20 сообщений, старые отбрасываем без
суммаризации. Результаты tool-вызовов остаются в истории.

**Системный промпт** несёт три обязанности: держать ответ в пределах 15–30 секунд
речи; опираться только на данные инструментов и честно сообщать о пустом результате;
проверять скидки Chocolife для мест, найденных в 2GIS.

### Custom skill — ресторанный критик

`analyze_restaurant_photo(image_path: str) -> RestaurantVerdict` — vision-вызов с
Pydantic-схемой: `level` (фастфуд / casual / mid-range / fine dining), `status`
(семейный, романтический, бизнес-ланч, молодёжный), `description`, `confidence`.
Параметры: `detail: "low"`, низкая температура.

Инструмент вызывает сам агент, когда видит фото ресторана, — не UI при загрузке
файла. Это прямо влияет на оценку критерия, поэтому оговорено в системном промпте,
а факт вызова виден в логе инструментов.

### Gradio

Слева чат с историей и три входа: текстовое поле, микрофон
(`gr.Audio(sources=["microphone", "upload"])`), картинка. Справа — плеер аудио,
плеер видео и раскрывающийся лог tool-вызовов (имя, аргументы, число записей).
Лог — доказательство на защите, что MCP реально дёргается.

Текст приходит всегда и сразу. Медиа генерируются только по нажатию кнопки
«Озвучить последний ответ»; два чекбокса рядом с ней — «озвучить голосом» (включён)
и «сгенерировать видео» (выключен) — определяют, докуда доходит генерация: только
TTS или TTS плюс видео. Автоматической генерации медиа при ответе нет.

## Обработка ошибок

| Слой | Поведение |
|---|---|
| Парсер не нашёл данных | Пустой список + `error` в ответе инструмента, агент отвечает честно |
| fal упал или таймаут | Текстовый ответ остаётся в чате, рядом плашка «видео не сгенерировалось», диалог продолжается |
| Нет ключа в `.env` | Падение на старте со списком недостающих переменных |
| Любое исключение в UI | `gr.Error` с русским сообщением, без голого трейсбека |

## Тестирование

`pytest`, три группы, ни одна не ходит в сеть:

1. **Парсеры** — на сохранённых HTML-фикстурах в `tests/fixtures/`.
2. **Мост MCP → tool-схемы и диспетчер** — на фейковом MCP-сервере.
3. **Цикл агента** — на заглушке LLM, возвращающей `tool_calls` по сценарию;
   проверяем ответ на каждый вызов из пачки и срабатывание потолка итераций.

## Конфигурация

Ключи берутся из корневого `.env` репозитория: `OPENAI_API_KEY`, `FALAI_API_KEY`
(копируется в `FAL_KEY`, который читает SDK), опционально `GEMINI_API_KEY`.
В `.env.example` — те же имена без значений. Модель LLM, модель аватара, лимиты
итераций, TTL кэша и пути задаются в `config.py`.

## Оптимизация стоимости (бонусные +10)

1. `detail: "low"` для всех изображений, уходящих в vision.
2. TTL-кэш результатов парсинга — повторные запросы бесплатны.
3. Кэш `custom_voice_id` — голос клонируется один раз за проект.
4. TTS и видео только по явному действию пользователя, а не на каждый ответ.
5. Ограничение длины ответа в системном промпте — короче речь, дешевле видео.

## Что делает владелец проекта, а не агент

1. Предоставить аудиосэмпл голоса (10+ секунд) и фронтальное фото (512×512+)
   — кладутся в `assets-private/`.
2. Записать демо-видео 2–3 минуты для сдачи.
3. Подтвердить написание имени для `Имя_Фамилия.zip`.
4. Подтверждать первый вызов каждого платного типа.

## Критерии готовности

- Оба MCP-сервера запускаются как отдельные процессы, агент получает от них
  реальные данные, лог вызовов это показывает.
- Агент помнит контекст диалога в рамках сессии.
- Фото влияет на ответ; `analyze_restaurant_photo` вызывается самим агентом.
- Ответ озвучен клонированным голосом, видео с корректным lip sync получено.
- `pytest` проходит целиком без сети.
- README содержит все семь разделов, включая фактическую стоимость.
- ZIP собран без `venv/`, `.env`, `__pycache__/` и тяжёлых файлов моделей.
